## 1. 앱 (`4EVR0-Server`) 변경

### 산출물
- `app/core/metrics.py` (신설) — 커스텀 비즈니스 메트릭 + 단계 타이밍 헬퍼
- `app/services/recommend_service.py` — 추천 파이프라인 계측
- `app/main.py` — `/metrics` 노출 (`prometheus-fastapi-instrumentator`)
- `requirements.txt` — `prometheus-fastapi-instrumentator==7.1.0` 추가

### 정의한 메트릭
| 메트릭 | 타입 | 라벨 | 의미 |
|--------|------|------|------|
| `recommend_stage_latency_seconds` | Histogram | `stage` (extract/neo4j/llm_response) | 단계별 처리시간 분해 |
| `profile_extraction_method_total` | Counter | `method` (llm/rule_based) | **폴백률 = LLM 장애 조기경보** |
| `recommend_requests_total` | Counter | `status` (ok/error) | 추천 요청 성공/실패 |
| `recommend_ingredients_found` | Histogram | - | Neo4j 반환 성분 수 (0개 = 회귀 신호) |

추천 흐름(`recommend()`)을 `with metrics.track_stage("extract"|"neo4j"|"llm_response")` 로
감싸 단계별 wall-clock을 기록하고, 폴백 method·성분 수·요청 결과를 함께 집계한다.
요청 전체를 `try/except`로 감싸 실패 시 `status="error"`를 카운트하고 예외는 그대로 재전파.

### 의존성 이슈 (해결)
- `prometheus-fastapi-instrumentator` **최신 8.0.2는 starlette≥1.0 요구** → fastapi 0.115.12
  (starlette<0.47)와 충돌(ResolutionImpossible).
- → **7.1.0** (starlette<1.0)으로 핀. fastapi 0.115.12 + starlette 0.46.2 정상 설치.

## 2. 인프라 (`Monitoring_Infra`) 변경

- `prometheus.yml` — `was-app` 스크레이프 잡 추가
  - 타깃: `macbook-pro-3.tailb70036.ts.net:8000` (이 Mac의 MagicDNS, vLLM과 같은 tailnet → pull 가능)
  - ⚠️ 앱이 개발자 Mac 로컬이라 상시 가동 아님 → 앱 꺼지면 타깃 down(정상).
- `config/dashboards/vllm.json` — **"앱 파이프라인 (WAS)" 행 + 패널 4개** 추가 (12 → 16 패널)
  | 패널 | 쿼리 핵심 |
  |------|-----------|
  | 단계별 평균 처리시간 (스택) | `rate(...sum)/rate(...count)` by `stage` → 추출/Neo4j/응답 분해 |
  | 프로필 추출 폴백률 | `rate(method="rule_based") / rate(전체)` |
  | 추천 요청 처리율 (ok/error) | `rate(recommend_requests_total)` by `status` |
  | 성분 0개 응답 비율 | `rate(..._bucket{le="0.0"}) / rate(..._count)` |
- `config/dashboards/README.md` — 앱 파이프라인 행 설명 추가

## 3. 동작 검증

- `pip install -r requirements.txt` — 의존성 충돌 없이 설치(7.1.0).
- `app.main` import OK, `TestClient` 로 `GET /metrics` → **200**.
- 커스텀 메트릭 4종 + 기본 HTTP 메트릭 모두 `/metrics` 노출 확인.
- 메트릭 기록 시뮬레이션: stage별 count, method 라벨, status 라벨,
  ingredients 히스토그램 버킷(0 → le=0.0, 12 → le=20.0) 정상 집계.
- `py_compile` 통과.

> 남은 검증(런타임): 실제 추천 트래픽을 흘려 Grafana 앱 파이프라인 행에서
> "추출/Neo4j/응답" 분해가 5/18 리뷰 수치처럼 재현되는지 확인 — 앱+Neo4j+vLLM 기동 필요.
