## 1. 산출물

| 파일 | 내용 |
|------|------|
| `eval/dataset.jsonl` | 정답셋 19개 — 메시지 + 기대 `skin_types`/`concerns`/`constraints` |
| `eval/run_eval.py` | 평가 러너 — 추출 실행 → 정확도/무효값/폴백/지연/토큰 산출 → `results.json` |

### 정답셋 (eval/dataset.jsonl)
- `test_e2e.py` 시드 5개 + 확장 14개 = **19개**. enum 기준 라벨, **무효 라벨 0**, concern **25/26종 커버**.
- 구성: 단일/다중 고민, 제약(향료·비건·저자극·알코올프리·EWG), 엣지(고민 없음=네거티브, 다중 스트레스).
- 라벨 기준: `app/domain/enums.py` + `taxonomy_normalization_service.py` 동의어 사전.
  > ⚠️ **부트스트랩 초안 — 팀 검토 필요.** 모호 케이스(예: id8 수부지 → COMBINATION+DEHYDRATED) 라벨 합의 권장.

### 평가 러너 (eval/run_eval.py)
산출 메트릭:
- **concern F1** (micro P/R/F1), concern 완전일치율
- **skin_type 정확도**(집합 일치), constraint F1, profile 완전일치율
- **무효값(오타) 비율** — enum에 없는 값 검출 (예: `POROUS_CONGESTION`) → 기존 회귀 이슈 고정 감시
- **폴백/에러 비율** — 추출 예외(vLLM 다운/타임아웃/파싱 실패)
- **latency p50/p90**, 평균 토큰(in/out)
- 프롬프트는 `llm_client._SYSTEM_PROMPT` 재사용, **프롬프트 해시(prompt_version)** 자동 기록 → 프롬프트 바뀌면 버전 추적
- 출력 `run`/`metrics` 딕셔너리는 **MLflow `log_params`/`log_metrics` 로 그대로 넘기기 쉽게** 구성(다음 스텝)

```bash
python eval/run_eval.py            # vLLM 가동 + .env 모델명 일치 필요
python eval/run_eval.py --limit 5
```
