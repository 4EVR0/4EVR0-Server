# 2026-06-26 작업 리뷰 (Phase 4 — 2차: MLflow + 프롬프트 버전 분리)

## 오늘 한 일: MLflow 실험 추적 연동 + 프롬프트 코드 분리

Phase 4 1차(정답셋 + 평가 러너)에 이어, **실험을 기록·비교**할 수 있게 MLflow를 붙이고,
하드코딩돼 있던 프롬프트를 **버전 관리 가능한 파일**로 분리했다.

## 1. 프롬프트 버전 분리 (`app/prompts/`)

| 파일 | 내용 |
|------|------|
| `app/prompts/__init__.py` | `load_prompt(name)` / `prompt_version(name)`(내용 sha1[:8]) |
| `app/prompts/profile_extraction.txt` | 추출 프롬프트 (구 `llm_client._SYSTEM_PROMPT`) |
| `app/prompts/recommend_response.txt` | 응답 프롬프트 (구 `recommend_service._SYSTEM_PROMPT`) |

- `llm_client.py` / `recommend_service.py` 는 이제 파일에서 로드. 동작 동일(프롬프트 텍스트 보존).
- **프롬프트가 바뀌면 `prompt_version` 해시도 바뀜** → 실험에서 "어떤 프롬프트로 측정했나" 식별.
- A/B 비교: `profile_extraction.v2.txt` 추가 후 `load_prompt("profile_extraction.v2")`.
- 현재 버전: 추출 `5774020c`, 응답 `76af3f07`.

## 2. MLflow 연동 (`eval/run_eval.py`)

- run 종료 시 자동으로 MLflow 기록 (`--no-mlflow` 로 끔).
- **params**: model, prompt_name, prompt_version, temperature, dataset, n_cases, n_scored
- **metrics**: concern_f1/precision/recall, exact_match, skin_type_accuracy, constraint_f1,
  invalid_value_rate, error_rate, latency_p50/p90, avg_tokens
- **artifact**: 케이스별 상세 results.json
- 백엔드: 기본 **sqlite `eval/mlflow.db`** (`MLFLOW_TRACKING_URI` 로 변경 가능), experiment `4evr0-profile-extraction`
- mlflow 는 **앱 런타임에 불필요** → `eval/requirements.txt` 로 분리(앱 이미지 경량 유지)

조회:
```bash
pip install -r eval/requirements.txt
python eval/run_eval.py                 # 측정 + MLflow 기록
mlflow ui --backend-store-uri sqlite:///eval/mlflow.db   # → localhost:5000 에서 run 비교
```
