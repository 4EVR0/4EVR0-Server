# 2026-07-25 — 지시적 후속("이 중에서") 맥락 직전-턴 한정

## 배경 / 문제
멀티턴 대화에서 사용자가 `"이 중에서 지성 피부에 적합한 거 추천해줘"`처럼
**직전 추천 세트를 콕 집어 좁히는(지시적/deictic) 후속 요청**을 할 때,
예전 턴의 대화 맥락(다른 피부 고민)이 섞여 들어가면 필터가 오염될 수 있음.

예)
- 턴1: "건조 피부 추천" → A, B, C
- 턴2: "지성 피부 추천" → D, E, F
- 턴3: "이 중에서 산뜻한 거" → **D,E,F 중에서 골라야** 하는데, 옛 "건조" 맥락이 새면 안 됨.

## 진단 (변경 전 코드)
`app/services/recommend_service.py`

- ✅ **제품 후보는 이미 직전 턴만** 봄:
  `last = next((t for t in reversed(history) if t.get("products")), None)` (515/540행).
  → "이 중에서"의 후보 제품은 옛 턴이 아니라 직전 추천 세트로 이미 한정돼 있었음.
- ⚠️ **새는 곳은 딱 하나** — `_followup_context`가 LLM 프롬프트에 넣는
  "이전 대화" 텍스트 블록이 `history[-3:]`(최근 3턴)이라, 옛 고민 텍스트가 섞임.

(참고: 스트리밍 경로 `recommend_stream`은 후속을 처리하지 않으므로 비스트리밍
`recommend()` 경로가 유일한 후속 처리 경로 — 이번 수정으로 충분.)

## 결정
`AskUserQuestion` 결과: **지시적 요청에만** "직전 턴만 참조" 규칙 적용.
"비교해줘" 같은 일반 후속은 여러 턴 맥락이 도움이 되므로 기존(최근 3턴) 유지.

## 변경 (`app/services/recommend_service.py`, +22 −4)
1. `_DEICTIC_CUES` + `_is_deictic()` 추가 — "그 중/이 중/저 중/중에서/이것들/그것들" 감지.
2. `_followup_context(..., deictic=False)` 파라미터 추가 —
   `deictic=True`면 "이전 대화" 블록을 `[last]`(직전 추천 턴) 하나로 한정,
   아니면 기존대로 `history[-3:]`.
3. `_handle_followup`에서 `deictic=_is_deictic(message)` 전달.

## 검증
- **유닛(합성 이력)**: 턴1=건조, 턴2=지성일 때
  `deictic=True` → 컨텍스트에 "지성"만, "건조" 배제 ✅ / `deictic=False` → 둘 다 포함 ✅.
- **라이브(Docker 리빌드 후 3턴 대화)**:
  - 턴1 건조 → 6개 제품 / 턴2 지성 → 4개 제품(피지오겔·헤라·차앤박).
  - 턴3 "이 중에서 가장 산뜻한 거" → **후보 = 턴2 지성 제품 4개 그대로**, 순위만 재정렬.
    턴1 건조 제품 **0개 유입**. 응답 텍스트도 지성 맥락(T존·피지·번들거림)만.

## 남은 것 / 후속 아이디어
- `_is_deictic`는 문자열 큐 기반 — 애매한 지시 표현은 못 잡을 수 있음(현 휴리스틱 정책과 동일 수준).
- 스트리밍 경로가 후속을 아예 처리하지 않는 기존 불일치는 이번 범위 밖(별도 과제).
