# LLM 쿼리 생성 품질 실험 — 발표용 요약

## 1. 배경 / 문제 정의

- 지금 추천 서비스는 LLM이 사용자 문장에서 **concern(고민)만 추출**하고, 그 뒤는
  전부 엔지니어가 미리 짜둔 고정 로직(딕셔너리 매핑 + 고정 Cypher 쿼리)을 탐
- 즉 LLM은 "빈칸 채우기"만 하고, 실제 그래프 탐색 경로는 사람이 미리 정해둠
- **질문**: LLM에게 그래프 스키마를 통째로 주고 쿼리 자체를 직접 짜게 하면,
  추천 품질이 더 좋아질까?

## 2. 비교 대상

| | 고정 쿼리 (A) | LLM 생성 쿼리 (B) |
|---|---|---|
| 누가 경로를 정하는가 | 엔지니어 (사전 정의) | LLM (질문마다 즉석 판단) |
| 지금 상태 | 프로덕션 실제 운영 중 | 이번 실험 대상 |

**판단 기준**: A가 이기면 지금처럼 고정 유지. B가 이기면 "RDB로 바꿔도 될지"까지
후속 비교(B vs D, 아직 미착수).

## 3. A(고정)는 어떻게 만들었나

프로덕션이 실제로 쓰는 함수를 **그대로 호출** (텍스트 복사 안 함 — 복사본은
원본과 어긋날 위험이 있어서, 실제로 이번 작업 중 여러 번 발견됨):

```
① query_ingredients_by_effects   — 효능 → 성분 조회 (AFFECTS 관계)
② apply_caution_filter           — 민감성 고민이면 자극 유발 성분 제외 (CAUTION 관계)
③ select_products                — 성분 → 제품 조회 + 카테고리 필터 + 리뷰 재정렬
```

## 4. B(가변)는 어떻게 만들었나

LLM에게 원문 메시지만 주고, 그래프 스키마 전체(4개 관계: CONTAINS/AFFECTS/
RELATES_TO/CAUTION)를 노출한 뒤 Cypher를 직접 생성시킴:

```
① 메시지 분석      — 관련 고민 파악
② 경로 선택        — Concern으로 먼저 매치할지, Effect 코드로 바로 갈지 LLM이 판단
③ 제품까지 도달    — Product-CONTAINS→Ingredient-AFFECTS→Effect
④ (필요시) 회피 조건 반영 — 민감성/저자극 언급 시 CAUTION으로 제외
⑤ 문법 검증 + 실행 — 결과 0건/에러면 이유를 알려주고 1회 재생성
```

## 5. 품질 채점 기준 3가지

기존 성분 단위 정답(pubmed 논문 근거)만으로는 "제품 추천이 좋은가"를 잴 수
없어서 새로 정함:

1. **category_fit** — 반환된 제품 카테고리가 고민에 적합한가 (씻어내는 제품 등 배제)
2. **ingredient_grounded** — 그 제품이 실제로 근거 있는 성분을 포함하는가
3. **review_score** — 올리브영 **실구매자 리뷰 태그**(보습/주름·미백/진정)와
   일치하는 비율 → 그래프와 무관한 **독립적인 검증 신호**

## 6. 테스트 데이터

- 기존 프로필 추출 평가용 정답셋(`eval/dataset.jsonl`) 재사용 — "피지는 많은데
  속은 건조하고, 좁쌀과 막힌 모공에 여드름 자국까지 있어요" 처럼 **여러 고민이
  섞인 실제 발화 스타일**, 46개 시나리오
- 그 중 12개(26%)는 민감성 계열 고민 포함 → CAUTION 배제 경로도 실제로 테스트됨

## 7. 실행 순서 (요약)

```
1. 시나리오 로드 (dataset.jsonl 46개)
2. 시나리오별로:
     A 실행 → category_fit / ingredient_grounded / review_score 채점
     B 실행 (LLM 생성 → 검증 → 실행, 실패 시 재시도) → 동일 기준으로 채점
3. 시나리오별 A vs B 결과 출력 + 전체 평균 집계
4. 실패율(b_failure_rate) 별도 집계 — 실패와 저품질을 구분해서 봄
5. 결과 JSON 저장 → 이후 분석/보고서 재료로 사용
```

```bash
python run_ab.py --limit 3   # 먼저 3개로 파이프라인 확인
python run_ab.py             # 전체 46개 실행
```

## 8. 준비 과정에서 발견/수정한 것 (신뢰성 확보)

- **정답 기준 자체의 정합성 확보**: 우리가 참고하던 여러 "정답 사본"들이 실제
  프로덕션 코드와 어긋나 있던 걸 발견 → 전부 사본 대신 원본을 직접 참조하도록 수정
- **그래프 데이터 공백 발견 및 보강**: 26개 고민 중 19개가 그래프 안에서
  경로를 못 찾는 상태였음(Concern 노드 자체가 없거나 연결이 없음) → 프로덕션
  로직을 그래프에 반영해서 26개 전부 경로 확보
- **평가 방법 자체의 오류 방지**: few-shot 예시가 테스트 문제와 겹쳐서 결과가
  왜곡되는 문제, 검증 로직이 "결과 0건"을 못 잡던 문제 등을 실행하며 발견해서 수정

## 9. 현재 상태

- 로컬 환경에서 A 경로(고정)는 정상 동작 검증 완료
- B 경로(LLM 생성)는 GPU 서버 연결이 있어야 실제 결과 확인 가능 — **아직 미실행**
- 다음 단계: GPU 서버에서 46개 시나리오 전체 실행 → A vs B 지표 비교 → 우위
  판단 → (B 우위 시) RDB 버전과 추가 비교
